# 07. 리소스 정리

## 개요와 학습 목표

이번 실습에서 사용한 리소스들은 사용한 시간만큼 과금되는 리소스들입니다. 실습이 끝난 후, 꼭 리소스를 정리하여 불필요한 과금이 일어나지 않도록 해야 합니다.

## 사전 요구사항

실습에 사용한 리소스와 구독·리소스 그룹을 확인합니다. 리소스 삭제 권한이 필요합니다. 공유 리소스나 실습 외 리소스를 함께 삭제하지 않도록 삭제 대상 목록을 먼저 확인합니다.

## 예상 소요 시간

약 15분을 예상합니다. 삭제 대상 확인, Azure 리소스 삭제 대기, 로컬 컨테이너·키·context 정리를 포함한 계획값이며 실측값은 아닙니다. 삭제가 지연되면 시간을 넘기더라도 리소스가 남아 있지 않은지 끝까지 확인합니다.

## 실습 단계

### 삭제 대상 확인

Azure 포털에서 실습에 사용한 구독을 선택합니다. `AKSWorkshopResourceGroup`의 리소스 목록을 확인하고, 실습 외 리소스가 있다면 그룹 전체를 삭제하지 말고 강사나 구독 관리자와 삭제 범위를 먼저 확인합니다.

삭제 전에 AKS 개요에서 노드 리소스 그룹을, Log Analytics 작업 영역에서 해당 리소스 그룹을 확인해 둡니다. 실습 중 이름을 변경했다면 아래 단계에도 변경한 이름을 사용합니다.

> **주의:** 리소스 그룹을 삭제하면 그룹 안의 리소스를 함께 삭제합니다. 필요한 데이터는 먼저 보관하고 실습 전용 그룹인지 확인합니다.

### 클라우드 리소스 삭제

1. Azure 포털 서비스 검색 상자에서 `리소스 그룹`을 입력합니다.
2. 목록에서 `AKSWorkshopResourceGroup`을 클릭합니다.
3. 상단에 `리소스 그룹 삭제` 버튼을 클릭합니다.
4. 확인 창에 `AKSWorkshopResourceGroup`을 입력하고 `삭제`를 클릭합니다.
5. 삭제 요청 완료를 기다립니다. AKS 삭제 시 노드 리소스 그룹과 그 안의 관리 리소스도 삭제됩니다.
6. 다른 그룹에 만든 실습 전용 Log Analytics 작업 영역 등 부수 리소스가 남아 있는지 확인합니다. 공유 그룹은 전체 삭제하지 않고 자신이 만든 실습 전용 리소스만 선택해 삭제합니다.

### 로컬 컨테이너 정리

샘플 앱을 실행했던 `aks-store-demo` 폴더에서 다음 명령을 실행합니다. 다른 프로젝트가 아닌 실습의 Compose 파일인지 먼저 확인합니다.

```console
docker compose -f docker-compose-quickstart.yml down
docker compose -f docker-compose-quickstart.yml ps
```

`down`은 해당 Compose 프로젝트의 컨테이너와 네트워크를 정리합니다. 빌드 이미지와 볼륨은 기본적으로 삭제하지 않으므로, 다른 실습에서 재사용할 수 있습니다.

### 로컬 키와 클러스터 연결 정리

로컬 manifest의 `ORDER_QUEUE_PASSWORD`를 `<your-service-bus-sender-key>`로 되돌리고 저장합니다. 키를 따로 복사한 파일이 있다면 실제 키도 제거합니다. 실제 키가 Git이나 공유 문서에 노출됐다면 단순 파일 삭제만으로 해결되지 않으므로 담당자에게 알리고 키를 재발급해야 합니다.

클러스터 연결 목록은 다음 명령으로 확인합니다.

```console
kubectl config get-contexts
```

다른 클러스터 연결은 보존합니다. 삭제한 실습 클러스터의 context를 더 이상 쓰지 않을 때만 아래 명령의 `<workshop-context>`를 목록에서 확인한 정확한 이름으로 바꿔 실행합니다.

```console
kubectl config delete-context "<workshop-context>"
```

이 명령은 context만 제거합니다. kubeconfig 전체나 공유하는 사용자·클러스터 항목을 일괄 삭제하지 않습니다.

## 검증

다음 항목을 모두 확인하면 정리를 마친 것입니다.

- Azure 포털에서 대상 리소스 그룹 삭제가 완료됐습니다.
- 실습 AKS와 해당 노드 리소스 그룹, ACR, Service Bus 및 실습 전용 모니터링 리소스가 남아 있지 않습니다.
- 실습 Compose 프로젝트에 실행 중인 컨테이너가 없습니다.
- 로컬 manifest와 따로 저장한 파일에 실제 Service Bus 키가 남아 있지 않습니다.

## 트러블슈팅

| 증상 | 확인과 조치 |
|---|---|
| 리소스 그룹 삭제 권한이 없음 | 로그인한 구독·계정을 확인하고 구독 관리자에게 실습 리소스 삭제를 요청합니다. |
| 삭제 잠금으로 요청이 거부됨 | 포털의 잠금과 활동 로그를 확인합니다. 공유 리소스의 잠금을 임의로 해제하지 말고 관리자와 삭제 범위를 확인합니다. |
| 노드 리소스 그룹이 남아 있음 | AKS 삭제 작업 상태와 오류를 확인합니다. 관리 리소스 그룹을 먼저 수동 삭제하지 않습니다. |
| 모니터링 리소스가 남아 있음 | 삭제 전에 확인한 그룹에서 실습 전용 작업 영역인지 확인한 뒤 정리합니다. 공유 작업 영역은 유지합니다. |
| 로컬 컨테이너가 남아 있음 | 앱을 실행했던 샘플 폴더·Compose 파일을 사용했는지 확인합니다. 다른 프로젝트의 컨테이너는 정리 대상이 아닙니다. |
